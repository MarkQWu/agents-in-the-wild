# 个人学习系统总纲

这是一个**学习别人 AI agent 仓库**的个人系统。仓库是 fork 自 [xiaolai/nlpm-for-claude](https://github.com/xiaolai/nlpm-for-claude)，在他的 NLPM（自然语言编程审计）基础设施之上加了一层「自查 + 灵感」的中文学习案例生成。

---

## 一、它在干什么

每天自动产出 4-6 篇深度学习案例。每篇案例研究一个真实的 AI agent 仓库（≥500 stars），从**模式**、**缺陷**、**架构**、**设计思路**四个维度提炼可学习内容，并产出**可执行的自查命令**和**灵感的实施路径**。

**目的不是产出 PR 贡献给别人**，而是通过分析别人的工程实践，**对照、校准、改进自己的 vault 和 skill 体系**。

---

## 二、系统组件

```
agents-in-the-wild/
├── auditor/                       # xiaolai 的 NLPM 审计基础设施（不动）
│   ├── audits/                    # 209 份 audit 报告（每周从上游同步）
│   ├── registry/repos.json        # 仓库元数据（stars、PR 历史等）
│   └── ...
├── case-studies/                  # 案例区
│   ├── *.md                       # xiaolai 的英文 engagement 故事（从上游同步）
│   └── learning/                  # 我的中文学习案例
│       ├── INDEX.md               # 全部案例索引（按时间降序）
│       ├── PROGRESS.md            # 进度看板（自动维护）
│       └── YYYY-MM/               # 按年-月分子目录
│           └── YYYY-MM-DD-slug.md
├── learning/                      # 我的学习层配置
│   ├── README.md                  # 本文件（系统总纲）
│   └── template.md                # 案例模板（改它 = 改未来所有案例结构）
└── .github/workflows/
    └── sync-upstream.yml          # 每周日 23:00 UTC 拉上游
```

                   │ sync-upstream.yml 每周日 23:00 UTC 同步
                   ↓

                   ↓

                   │

## 四、怎么读案例

每篇案例按 5 章组织，对应学习的 5 个阶段：

| 章节 | 阶段 | 重点 |
|---|---|---|
| 一、理解 | 把握全貌 | 架构剖析 + 设计思路（基于当前仓库 HEAD） |
| 二、过去审查发现 | 看历史教训 | 当时的评分、缺陷、模式（带 audit 日期） |
| 三、现在 vs 过去对比 | 看演进 | 缺陷修了没、架构改了没、有没有新增模式 |
| 四、校准 | 自我对照 | 我已在做对的 + 这次挑战了我什么假设 |
| 五、行动 | 落地 | 可直接复制粘贴的 grep 自查命令 + 灵感的第一步 |

**正确的阅读姿势**：

1. **不要从头读到尾**——案例信息密度很高，按需取用
2. **先看「五、行动」**——拿到自查命令，去自己 vault 跑一次
3. **命中后**回头看「二、当时的缺陷」对应条目，理解为什么这是个错
4. **如果命中频繁**，看「值得借鉴的模式」考虑系统性改进
5. **季度复盘**时，看「三、对比」帮助识别"这个领域真的能改进"的信号

## 五、修改入口

| 你想改什么 | 改这个文件 |
|---|---|
| 案例结构（增减 section）| `learning/template.md` |
| 每天处理数量、过滤规则、新模式 | Routine 提示词（[管理页](https://claude.ai/code/routines/trig_01Y2rfGRGFrACHrkrhCh3RSA)） |
| 上游同步频率 | `.github/workflows/sync-upstream.yml` |
| 总纲（本文件） | `learning/README.md` |
| 主题标签集合 | `learning/template.md` 底部「主题标签约定」 |

## 六、关键边界

- **不要直接拿「优化机会」section 去给上游开 PR**：那是基于 audit 快照的，可能已经被修复（参见每篇案例顶部的 ⚠️ 警告）
- **如果真要 PR 给某个仓库**：走 `auditor-contribute.yml` workflow（标 `contribute-approved`），它会重新跑 audit 再开 PR，避免重复劳动
- **本地 audit 的产出**会被这套学习系统优先处理（除 4 篇 upstream 配额外，所有本地 audit 都会生成案例）

## 七、维护节奏

| 频率 | 谁做 | 做什么 |
|---|---|---|
| 每天 02:00 UTC | Routine | 产 4-6 篇案例 → 开 PR |
| 每天 | 你 | merge PR / 拒绝重做 |
| 每周日 23:00 UTC | sync-upstream.yml | 拉 xiaolai 新增 audit |
| 每周一 02:00 UTC | Routine | 自动产出 weekly digest |
| 每月底 | 你 | 看 PROGRESS.md 估算节奏，看 weekly digest 找跨案例规律 |
| 每季度 | 你 | 复盘哪些"自查动作"反复命中，把高频规则升级到自己的 `.claude/rules/` |

---

**核心心法**：xiaolai 写 NLPM 时假设「我第一版规则一定是错的」，所以建了自我修正机制。你用这套学习系统时，也要假设「我第一次自查命令一定不准、第一次灵感一定不切」——通过持续跑、持续命中、持续修正，让这套系统跟你一起进化。
