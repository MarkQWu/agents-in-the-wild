## 二、本周最重要的三个认知

### 认知 1：NL 质量分 98/100 的仓库可以同时被安全门封锁——两个维度正交，互不干涉

本周最反直觉的案例是 `zhukunpenglinyutong/jetbrains-cc-gui`。它的唯一 NL 工件（Vercel React 最佳实践 SKILL.md）得了 98/100——70 条带编号规则、8 个优先级层次、每条规则附 before/after 代码对比，几乎是 NLPM 评分体系里能看到的最完整的单个 skill 文件。

但同一个仓库，ai-bridge 层有两个 HIGH 安全发现：`spawn()` + `shell: true` 接受用户提供的 MCP 服务器命令字符串，可被恶意 MCP 配置触发 shell 注入。NLPM 整体评级：**BLOCKED**。这意味着 PR 不提交，发现不上报。

三个月后（当前 HEAD），这两个 HIGH 发现仍在原位。`stdio-tools-getter.js:104` 和 `stdio-verifier.js:87` 的 `spawnOptions.shell = true` 仍然是原来那几行代码。

这里有一个值得警惕的认知陷阱：**高 NLPM 分往往让维护者觉得系统质量很好**。如果作者只看 NL 评分（98/100），会得到「仓库没问题」的错误信号——但真正的问题在执行层，而 NLPM 的 NL 评分根本不覆盖那里。

**行动意义**：任何含有执行层（Python 脚本、Node.js 文件、shell 脚本）的 Claude Code 插件，NL 质量分是不充分的——必须额外进行独立的安全审查，不能用 NL 分数替代安全评估。

### 认知 2：bug 修复的时效性与 NLPM 评分无关，与「audit 报告的可操作性」正相关

本周有三个仓库的 audit 发现状态形成了鲜明对比：

得分最低（72分）的仓库没修，得分最高（98分）的仓库也没修，而中间的仓库（88分）反而全修了——评分与修复速度无关。

决定修复速度的是另一个变量：**audit 报告的可操作性**。`geo-seo-claude` 的 NLPM 报告给出了精确的文件名 + 行号（`skills/geo-report/SKILL.md:23`，`scripts/webapp/app.py:214`）和具体的修复代码示例。维护者把报告直接当 checklist，启动 Claude Code session，16 秒内合并 5 个 PR。

而 `zhsama` 的两个 bug（缺少 `name:` + 名称不匹配）同样是精确的行号指向，但 audit 报告以 Issue 形式提交到 GitHub，维护者未响应。可操作性够，但缺乏「执行触发器」（没有本地 Claude Code session 等待 checklist）。

**行动意义**：写自查 checklist 时，精确到文件名和行号是关键——「检查是否有问题」和「改 `commands/agent-workflow.md` 第 1-5 行，添加 `name: agent-workflow`」之间的差距，就是「知道问题」和「Claude 能直接执行修复」之间的差距。

### 认知 3：「批量创建」带来「批量技术债」——模板缺陷的乘数效应

本周看了两个规模极为不同的「批量 agent 集合」：zebbern（110 个 agent）和 zhsama（12 个 agent）。它们有同一个问题：**全部 agent 缺少 `model:` 声明**。

这不是巧合——是「批量创建时使用了不完整模板」的直接后果。作者在创建第一个 agent 时，模板里没有 `model:` 字段；之后的 109 个 agent 都从这个模板 copy 过来。结果：一个单点缺陷，被复制 109 次。

这是一种特殊的技术债——**乘数效应**：缺陷 × 文件数 = 实际债务规模。zebbern 的 `model:` 缺失，一次 `sed` 命令可以修复所有 110 个文件，但如果不修，这 110 个文件每一个都是潜在问题点，随着仓库扩充继续增长。

另一个维度的「乘数效应」出现在 zebbern 的模糊量词：audit 时 top-web-vulnerabilities SKILL.md 有 17 行模糊量词（命中 -20 上限）。到当前 HEAD，同一文件降至 5 行——说明作者有意识地在改，但没有对全体文件批量清扫。这种「选择性修复」正是技术债的积累方式：修了最显眼的，忽略了其余。

本周同期看的 superset-sh/superset（64/100，本批最低分）也是同类问题：大规模仓库的 NL 工件从未统一审查，小缺陷在数十个文件中累积，单点修复无法根治。

**行动意义**：
1. 在创建任何「将被批量复制的模板」时，确认模板本身通过 NLPM 评分（≥90分）才开始批量复制
2. 对批量创建的工件，用脚本而非手工进行批量检查（`grep -L "^model:" agents/*.md`）
3. 「选择性修复」不可持续——要么用批量命令（`sed -i`）一次性修复，要么接受债务持续增长
