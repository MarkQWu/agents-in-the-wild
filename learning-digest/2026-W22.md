## 二、本周最重要的三个认知

### 认知 1：star 数 ≠ NL 质量 ≠ 安全性

本周看了 NousResearch/hermes-agent（94k stars）和 BayramAnnakov/claude-reflect（1k stars）的鲜明对比：
- hermes-agent：80/100 NLPM，安全 BLOCKED（8 个 CRITICAL），shell=True 漏洞两个月后仍在
- claude-reflect：99/100 NLPM，安全 CLEAR，代码极度精简

质量不由星数决定。高 star 仓库往往因为快速增长、贡献者众多、缺乏 CI 质量门槛，反而容易积累技术债。

**行动意义**：不要因为「别人 star 多所以我要模仿他的设计」。评估一个设计，看质量指标（NLPM 分数、安全评级）而不是 star 数。

### 认知 2：「动态文档」是有 CLI 核心的插件的正确姿势

MemPalace 的 SKILL.md 调用 `mempalace instructions <cmd>` 获取操作说明，而不是把步骤硬编码进 SKILL.md。好处：
- SKILL.md 不会随 CLI 版本迭代而漂移
- 用户总是看到最新的操作说明
- NL 层保持「薄」，核心逻辑在 CLI 里

对比：echo-sleuth 的 SKILL.md 里写了所有步骤，一旦 Python 脚本改动需要手动同步。

**行动意义**：给 echo-sleuth 的 Python 脚本加 `--instructions` 子命令，SKILL.md 改为调用它。

### 认知 3：用 AI 开发 AI 工具是可以结构化的

PeonPing 的 .gitban 管道（dispatcher→planner→executor→reviewer）把 AI 辅助开发流程化了——每次功能变更留有可追溯的文本记录，code review 由 AI reviewer 执行，但审批决策有迹可查。

这比「直接让 Claude 改代码然后 git commit」要严格得多。工具质量（严格多平台测试、无硬编码路径等）与这个流程直接相关。

**行动意义**：为 echo-sleuth 或 claude-for-legal 的下一次重构，尝试用 .gitban 的 L1/L2/L3 优先级格式编写变更任务卡，观察是否有助于提升执行质量。
