## 二、本周最重要的三个认知

### 认知 1：自主循环架构的"创建-检查-删除"三角约定

本周连续看了两个 Ralph 系列项目：ralph-wiggum-marketer（muratcankoylan）和 ralph-orchestrator（mikeyobrien）。两者都实现了「Stop hook → 阻断 Claude 退出 → 重新注入提示词」的自主循环，但有关键区别：

- ralph-orchestrator 设计完整，NL层+Rust运行时闭环
- ralph-wiggum-marketer 存在 B1 致命缺陷：`/ralph-marketer` 命令**从不创建**循环状态文件（`.claude/ralph-marketer-loop.local.md`），而 stop hook 检查此文件才会激活，`/ralph-cancel` 删除此文件来停止——三角中缺一角，整个循环功能永不激活

这个 bug 的根本原因是"隐性状态契约"：三个组件（command、hook、cancel）通过文件系统文件隐式协调，但协调规则没有在任何地方显式文档化，也没有测试保证它。

**行动意义**：我的任何多组件插件，凡是靠文件系统状态协调的，都要显式写出"创建者是谁、检查者是谁、删除者是谁"的三角约定。可以在 CLAUDE.md 里加一个 `## 状态文件契约` 节。

### 认知 2：文档和代码是异步维护的——漂移不可避免，除非有测试

musistudio/claude-code-router 的案例揭示了一个普遍现象：
- 英文文档写 "默认端口 8080"
- 实际代码（`packages/cli/src/cli.ts:143`）是 `PORT || 3456`
- 中文文档写的是 3456（正确的）

为什么出现分裂？大概率是某次代码改动改了端口号但只同步了中文文档忘记更新英文文档。这不是个别失误，是所有维护多语言文档项目的系统性风险。

godogen 的案例是同一个问题的另一种形态：做了根本性架构重构（双树→多引擎树），但 `concise` 模糊量词和缺失的 `## Output` 段原封不动地被带入新架构。质量问题跟随代码迁移而迁移，因为没有 CI 检查文档质量。

**行动意义**：给 echo-sleuth 的 README 里任何提到具体路径、端口、版本号的地方做一个 `# TODO: verify this matches code` 注释，下次改代码时 grep 这个注释提醒自己同步。更根本的做法：CI 里加一个简单的脚本，grep 文档里的关键值并和代码常量对比。

### 认知 3：单职责+编号步骤是达到 95+ 分的最短路径

本周两个最高分（itsmostafa 99/100，lackeyjb 98/100）有一个共同点：
- 极简设计：单一 SKILL.md，无 agent 层，无 command 层
- 用 `CRITICAL WORKFLOW — Follow these steps in order` + 编号步骤约束执行顺序
- 代码示例数量充足（lackeyjb 有 6 个代码示例 + 2 个交互示例）
- 零或极少模糊量词

对比 nicobailon/visual-explainer（66/100，本周最低分）：8 个命令全部缺少 `name` frontmatter，全部缺少 `allowed-tools` 声明，多个命令无空输入处理——每一条都是机械性失误，不是设计问题。

结论：高分和低分之间不是「谁的架构更复杂」，而是「谁把基础细节做对了」。`name` 字段缺失是纯机械问题，检查一次就能发现全部 8 个。

**行动意义**：运行 `/nlpm:score echo-sleuth-for-claude` 看有没有类似的机械性失误（缺 name、缺 allowed-tools、缺 output format），这些比架构重构更容易修、更快提分。
